# Leo Learn 项目介绍与运行手册

> 依据当前仓库实现核对，更新于 2026-09-21。内容创作请继续阅读 [文档编写与 AI 协作规范](content-authoring-guide.md)。历史 PRD 和设计稿用于了解背景，不能作为功能已经实现的证明。

## 1. 项目是什么

Leo Learn 是个人在本地使用的静态学习文档站。内容按“空间 → 多级目录 → 文档”组织。把 Markdown/MDX 和资源放进对应目录，启动网站即可自动生成导航和阅读页面；开发模式下保存文件会触发内容重新生成和页面刷新。

所有正文、目录介绍、空间信息和演示组件均通过修改仓库文件维护。页面不提供编辑器、后台管理、账号或数据库。收藏、阅读位置和主题选择保存在浏览器中，和仓库中的文章内容分开。

网站使用 React、TypeScript、Vite、MUI 与 MUI 图标。普通文档由 React Markdown 渲染；MDX 编译成 React 组件；公式使用 KaTeX，结构图使用 Mermaid，数据图表使用 Vega-Lite。页面为客户端路由应用，生产构建输出静态文件，并非每篇文章生成独立 HTML。

## 2. 当前能力

| 能力 | 实际使用方式 |
| --- | --- |
| 多文档空间 | 每个 `spaces/<空间目录>/space.yml` 定义一个空间 |
| 多级目录 | 按文件夹结构自动生成导航，可同时展开多个分支 |
| 目录总览 | 每层目录可用 `_index.md` 或 `_index.mdx` 编写介绍；无文件时生成占位目录页 |
| 富文本阅读 | Markdown、表格、代码高亮与复制、公式、提示块、图片放大、视频和音频 |
| 图表与示例 | Mermaid、Vega-Lite，以及带预览、源码和重置功能的 React Demo |
| 搜索 | 标题、标签、章节、简介、目录、正文、代码；按空间/标签/类型组合筛选 |
| 收藏 | 在文章中添加/取消，收藏页筛选；Header 入口不显示未读式数字徽标 |
| 阅读记忆 | 自动保存阅读位置，重访时尽量恢复；显式章节链接优先 |
| 主题 | 同一 UI 结构支持深浅色，选择保存在当前浏览器；首次默认深色 |
| 响应式 | 窄屏优先收起左侧导航，更窄时隐藏右侧文章目录；媒体和宽内容适配阅读区 |

标签点击后进入搜索筛选，没有独立的标签/专题索引页。开发阶段的示例空间和内部设计预览页已经移除；新安装时首页为空，需添加自己的空间。

## 3. 安装和日常运行

### 环境与首次启动

建议统一使用 Node.js 22.18+ 的 22.x 或 Node.js 24.x，以便运行直接导入 TypeScript 的现有测试。当前锁定依赖中的 Vite 7 要求 Node.js `^20.19.0 || >=22.12.0`；仅满足 Vite 的最低版本不代表能直接运行所有测试。

在仓库根目录执行：

```bash
node --version
npm ci
npm run dev
```

默认访问 `http://localhost:5173`，实际端口以终端输出为准。停止服务按 `Ctrl+C`。已有锁文件时使用 `npm ci` 重现依赖；主动调整依赖时才使用 `npm install` 并检查锁文件变化。

长期使用建议固定同一访问地址。浏览器把 `localhost`、`127.0.0.1`、不同协议和不同端口视为不同来源，收藏和阅读位置不会在这些地址之间共享。

### 命令一览

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 开发服务器；自动扫描、监听内容变化并刷新 |
| `npm run generate` | 生成内容和搜索数据，并重新复制空间资源 |
| `npm run check` | 生成数据并运行 `tsc --noEmit` |
| `npm test` | 运行全部自动化测试 |
| `npm run test:pages` | 部署子路径、正文链接与静态页面入口测试 |
| `npm run build` | 生成数据、类型检查、Vite 生产构建，输出到 `dist/` |
| `npm run preview` | 本地预览已构建的 `dist/`；内容变化后需要重新 build |
| `npm run test:search` | 内容搜索提取、匹配、排序和 URL 筛选测试 |
| `npm run test:bookmarks` | 收藏数据读写与文档匹配测试 |
| `npm run test:reading-memory` | 阅读记忆数据读写与清理测试 |
| `npm run test:layout` | 侧栏宽度限制与正文可用空间测试 |

`check` 不能代替实际页面验证：它不检查资源是否 404、交互是否正常、图表运行时语法是否有效。当前 tsconfig 只 include `src`，空间/共享 Demo 源码不属于完整类型检查范围；`build` 会编译它们，但也不能代替 Demo 类型审查与交互验证。

### 构建后运行

```bash
npm run build
npm run preview
```

不要直接双击 `dist/index.html` 作为正常访问方式。本地默认按域名根路径运行；部署到子目录时，通过 `VITE_BASE_PATH` 指定以 `/` 开头和结尾的路径。资源和正文链接自动使用此路径，站内路由、收藏和阅读记忆继续使用不带部署前缀的文章标识。

### GitHub Pages

本仓库通过 `.github/workflows/pages.yml` 自动部署到 [在线文档站](https://leochenkg.github.io/leo-docs/)。仓库 Settings → Pages 的发布来源设置为 **GitHub Actions**。推送到 `master` 或手动运行工作流后，会依次执行 `npm ci`、`npm test`、`npm run build`，再发布 `dist/`；构建失败时不会替换已发布站点。构建路径读取 Pages 配置，当前为 `/leo-docs/`。

构建会自动为已发布空间、文章、目录页、搜索和收藏页生成对应的 `index.html` 入口，因此文章链接可以直接访问和刷新；无需手动登记新文章路由。未知路径由 `404.html` 加载应用的“页面不存在”界面。页面内容仍由浏览器渲染，这些入口不是正文预渲染或服务端渲染。

本地检查与线上相同的子路径构建：

```bash
VITE_BASE_PATH=/leo-docs/ npm run build
VITE_BASE_PATH=/leo-docs/ npm run preview
```

打开 `http://localhost:4173/leo-docs/`。站点公开访问，文章、索引和随构建发布的资源均可下载；没有账号登录或访问控制。在线站点与本地站点的收藏、阅读位置和宽度设置分别保存在各自浏览器来源下，不会同步。部署结果和失败原因可在仓库 Actions 的 **Deploy GitHub Pages** 中查看。

不依赖网络的本地文档、资源和 Demo 可以本地阅读；引用远程媒体、外部数据或网络 API 的内容仍需要网络。项目没有离线缓存/PWA 安装功能。

## 4. 仓库各目录的职责

以下树形结构展示内容的放置方式，其中 `frontend` 和文章文件名仅作示意；当前 `spaces/desktop/` 保存桌面端空间，不会自动生成示例文章。

```text
leo-docs/
├── AGENTS.md                       AI 内容任务的简短入口
├── README.md                       项目入口、启动和文档链接
├── docs/
│   ├── project-guide.md            本手册：项目和运行
│   ├── content-authoring-guide.md  内容格式、实操、AI 工作流程
│   └── templates/                  可复制的内容与 Demo 模板
├── spaces/
│   └── frontend/
│       ├── space.yml               空间信息
│       ├── _index.md               空间首页正文
│       ├── basics/
│       │   ├── _index.md           目录总览正文
│       │   └── closure.mdx         文章
│       ├── assets/                 图片、音视频等静态资源
│       └── components/demos/       当前空间的演示组件
├── components/                     全站共享 Demo
├── scripts/
│   ├── content.mjs                 文件扫描、元数据、路由与资源生成
│   └── search-index.mjs            搜索正文与标题锚点提取
├── src/
│   ├── App.tsx                    布局、导航、文章和目录页、阅读恢复
│   ├── theme.ts                   MUI 主题与基础样式
│   ├── types.ts                   内容数据类型
│   ├── components/                内容渲染、搜索、收藏页面
│   ├── bookmarks/                 收藏的数据模型和存储
│   ├── reading-memory/            阅读位置的数据模型和存储
│   ├── search/                    搜索算法
│   └── generated/                 自动生成的数据，不手改
├── public/content/                自动复制的资源，不手改
├── dist/                          构建产物，不手改
└── vite.config.ts                 内容监听、MDX 编译和开发服务
```

`docs/` 是仓库说明，不会自动出现在网站导航。要发布一篇网站文章，应写到 `spaces/` 下有效空间中。

`site.config.ts` 目前存在，但没有被页面代码消费。修改它不会自动改变 Header 或浏览器标题；维护站点名称需查看 `src/App.tsx` 等实际实现。新增普通文章无需修改这些运行时代码。

### 数据生成过程

1. 扫描 `spaces/` 的一级目录，读取其中的 `space.yml`；没有非空配置文件的目录被跳过。
2. 递归收集 Markdown/MDX，忽略路径片段为 `assets` 或 `components` 的内容。
3. 解析 Front Matter，过滤草稿/隐藏文档，生成默认路由和目录占位页。
4. 抽取正文和标题，生成内容数据与搜索数据。
5. 将空间各级 `assets/` 里的文件复制到 `public/content/spaces/<slug>/...`。
6. 页面加载生成数据，MDX/Demo 按需加载。

`public/content/` 每次生成会整体重建；资源原件必须保留在 `spaces/`。删除/隐藏文档不是访问权限机制，资源也不会按文档隐藏状态逐项保护。

### 从零创建一个文档空间

例如创建一个“数据结构”空间：

```bash
mkdir -p spaces/data-structures/arrays/assets
touch spaces/data-structures/_index.md
```

写入 `spaces/data-structures/space.yml`：

```yaml
slug: data-structures
title: 数据结构
description: 用可运行的例子记录常用数据结构和算法。
order: 3
```

写入空间首页 `spaces/data-structures/_index.md`：

```md
---
title: 数据结构
description: 从数组、链表到树和图。
---

# 数据结构

这里说明这个空间的学习目标、前置知识和推荐入口。
```

再创建 `spaces/data-structures/arrays/_index.md` 和 `spaces/data-structures/arrays/basics.md`，保存文件后开发服务器会自动生成 `/spaces/data-structures/arrays` 目录页和 `/spaces/data-structures/arrays/basics` 文章页。新增的空间会出现在首页和 Header 的空间切换菜单中；若没有出现，先检查 YAML、目录名与 slug，再运行 `npm run generate`。

## 5. 阅读操作

### 导航和目录页

- Header 切换文档空间；点击“文档”品牌返回空间列表。
- 文件夹整行（包括文字、图标、箭头和空白）点击会切换展开/收起，并打开对应目录页。
- 目录展开相互独立。折叠父目录会隐藏整个分支，再展开时保留子分支在当前会话中的状态。
- 页面首次进入深层文档时展开当前路径；导航展开状态不写入浏览器持久存储。
- 右侧“本页目录”来自正文二级及更深标题，点击定位章节；浅色与深色的结构一致。
- 目录页自动追加“本目录”子项卡片，目前没有 Front Matter 字段可关闭卡片。
- 上一篇/下一篇仅在当前空间的同级普通文章之间按顺序计算，目录首页不参与。
- 短文下方的相邻文章导航通过空白撑到阅读区底部，保留自然的底部间距。

### 搜索

点击 Header 搜索或按 `Cmd/Ctrl + K`。上下键选择结果，回车打开，Esc 关闭。弹窗最多展示前 8 条，可进入完整搜索页。

关键词不区分大小写，支持中英文部分匹配；空格分隔的多个关键词需要同时命中，可以分散在不同字段。结果按相关度或最近更新排序。无关键词也可以按筛选条件浏览。

显式创建的目录总览参与搜索；系统自动生成的空目录页不参与。MDX 静态文本可检索，导入语句、表达式、组件属性和 Demo 运行时生成的内容不保证能检索，因此核心知识必须写在正文中。

### 收藏和阅读记忆

收藏入口没有通知徽标。数量只在收藏页展示；取消收藏后即从列表移除。收藏优先使用源文件路径匹配当前文章，其次用路由匹配；二者都改变时旧收藏会保留并提示暂不可用。

阅读记忆在滚动和离开页面时自动保存。恢复优先尝试保存的标题锚点，再按滚动比例/位置恢复；它不是逐字阅读进度。包含明确 `#章节` 的链接优先定位指定章节。最多保留 100 条、180 天内的记录，读取和后续写入时会整理过期数据。

两项数据均只属于当前浏览器来源；不会同步到 Git、其他设备或其他浏览器。主题也保存在本地。清除网站存储会清除这些状态，目前没有页面内导入/导出或批量清空工具。

## 6. 响应式布局

文章和目录总览的正文随窗口宽度伸缩，最大宽度为 1120px。正文在左侧导航与右侧本页目录之间居中，左右留白保持一致；达到上限后，新增空间平均分配到正文两侧。有章节时，本页目录占用独立的可调整宽度；没有本页目录时，正文在整个主内容区居中。包含根目录首页的空间概览也使用此布局；首页、搜索、收藏及未提供根目录首页的空间概览继续使用原有布局。窄屏仍保留页面内边距和设备安全区域。

右侧“本页目录”固定在视口右侧、顶部工具栏下方，不随正文滚出屏幕。目录高度超出可用视口时，仅目录自身纵向滚动。正文滚动或目录宽度变化时，当前章节的选中项会自动移入目录可视范围；自动跟随只调整目录，不改变正文滚动位置。

文档向下滚动超过 200px 后，显示“回到顶部”浮动按钮；点击后平滑返回页首，并清除当前章节锚点，避免刷新后又跳回该章节。按钮在有右侧目录时靠正文区域右下角放置，随目录宽度调整位置；窄屏靠视口右下角放置，并保留设备安全区域。返回顶部后按钮隐藏，键盘焦点回到文章标题。系统启用“减少动画”时立即回顶，不播放淡入淡出。实现参考 [MUI 文档站 BackToTop 组件](https://github.com/mui/material-ui/blob/cf3f914c950bf9134344ae56de8e42b746ae975c/packages-internal/core-docs/src/AppLayout/components/BackToTop.tsx)。

拖动左侧导航右边缘或右侧目录左边缘的分隔线可以调节宽度；侧栏隐藏时，其拖动条也隐藏。左侧导航默认 300px，最小 220px；右侧目录默认 200px（768–899px 屏幕）或 220px（更宽屏幕），最小 180px。两侧栏没有固定最大宽度，拖动时保持另一侧栏当前宽度，允许压缩正文，直到正文达到 240px 的最小宽度。可调上限由窗口、另一侧栏宽度及页面留白共同决定；手机布局按屏幕宽度自然收缩。正文继续保留目录占位，维持居中和两侧等距。

分隔线在悬停、拖动或键盘聚焦时只显示一条高亮竖线；鼠标拖动结束并移开后恢复普通分隔线。可通过 Tab 聚焦，用左右方向键移动，按住 Shift 可加快调整；Home/End 调到当前最小/最大宽度，双击恢复该侧默认宽度。宽度偏好保存在当前浏览器，刷新后保留；窗口临时收窄时自动适配，放宽后恢复偏好。

| 屏幕宽度 | 当前布局 |
| --- | --- |
| 1200px 及以上 | 左侧导航常驻，右侧目录在有章节时展示 |
| 768–1199px | 左侧改为菜单抽屉，保留右侧文章目录 |
| 767px 及以下 | 左侧使用抽屉，右侧目录隐藏 |
| 899px 及以下 | Header 搜索输入框改为搜索按钮 |
| 599px 及以下 | Header 隐藏空间切换器；可点击品牌回首页切换空间 |

正文支持安全区域留白。代码、公式、表格在自己的区域内横向滚动；图片可放大，视频使用原生控件。编写 Demo 时仍需检查 320px/375px/768px 等窄屏，不能只依赖外层容器修复固定宽度组件。

## 7. 维护和排查

| 问题 | 检查顺序 |
| --- | --- |
| 空间未显示 | 检查 `space.yml` 是否存在且非空、YAML 是否有效、`hidden` 是否为 true |
| 文档未显示 | 检查后缀、所在目录、`draft/hidden`，以及终端生成错误 |
| 目录只有占位提示 | 创建对应目录的 `_index.md` 并写入正文 |
| Duplicate route | 检查同名 md/mdx、重复 slug、`index.md` 与 `_index.md`、清洗后相同的路径 |
| 保存后未刷新 | 查看开发终端错误；执行 generate，必要时重启 dev |
| 图片/视频 404 | 检查原件是否在 assets、相对层级和大小写、生成后的资源 URL |
| MDX 编译失败 | 检查 JSX 闭合、花括号、组件名和 import；查看 build 的文件位置 |
| Demo 未找到 | 检查 `Demo.tsx` 大小写、默认导出、name、空间目录名与 slug 是否一致 |
| 最近更新时间不符合手填 date | 页面优先使用文件 mtime；修改 date 不覆盖最后更新时间 |
| 收藏或阅读位置“丢失” | 确认访问地址、端口、浏览器一致，且未清空网站存储 |

代码变更时同步维护对应手册，避免按历史设计稿推断当前能力。内容交付流程、模板与逐项验收见 [文档编写与 AI 协作规范](content-authoring-guide.md)。
